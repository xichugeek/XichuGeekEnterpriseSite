# AI 开发记录 · Project 001

## 原始需求

把“IT 小白如何从零利用 AI 搭建企业官网”落成一个可克隆、可修改、可静态构建、可 Docker 部署的开源 Starter。要求五个主要页面、响应式、SEO、文档和演示截图；禁止把虚构资料写成真实客户业绩，也不接入不必要的 AI API。

## 需求拆分

AI 将工作拆为：项目与 Git 基础、统一内容配置、共用布局和页面、响应式样式、SEO 路由、Docker/Nginx、使用与部署文档、浏览器验证及公开仓库安全检查。页面内容先采用明确标记的虚构公司示例。

## AI 生成的代码与材料

- Astro 页面、组件、TypeScript 配置和 Tailwind/CSS 样式。
- SEO 元数据、robots.txt、sitemap.xml、favicon 和分享封面。
- Dockerfile、Compose、Nginx 配置。
- README、部署指南和这份过程记录。

## 人工负责的判断

项目所有者确定技术栈、页面范围、内容真实性边界、唯一开发目录与 GitHub 仓库，并要求首次推送前完成构建、差异检查和敏感信息扫描。正式公司资料、域名、案例授权、上线时机及视频制作均需人工决策。本轮没有修改生产站或部署演示站。

## 遇到的问题与处理

- 初始目录为空且没有 Git 仓库：在指定目录初始化 `main` 并连接指定远端。
- 本机 Docker 命令不可用：保留容器配置并在交付结果中明确标记运行时未验证，不能假称通过。
- npm 官方源拉取 Vite 元数据时连接不稳定：首次安装改用可访问的镜像完成，再将锁文件地址统一改回 npm 官方源；`npm ci --offline` 随后通过。
- Windows 上运行预览服务时，原生 CSS 依赖文件被占用，导致一次 `npm ci` 报 `EPERM`：停止预览服务后重试通过。
- 演示内容可能被误认为真实资料：在全站顶栏、案例页面与文档中标记其虚构属性，使用 `example.com` 占位邮箱和域名。

## 如何验证

运行 `npm ci`、`npm run check`、`npm run build`、本地预览；用浏览器检查各路由、移动菜单、404、图片、favicon、robots 和 sitemap。按 1920×1080、1440×900、1280×800、390×844、375×812 检查布局，并保存页面截图。首次公开推送前审查 `.gitignore`、Git 差异、已跟踪文件与敏感信息扫描结果。

## 如何部署

Docker 多阶段构建先由 Node 编译静态站，再由 Nginx 运行。使用者在构建时设置自己的 `PUBLIC_SITE_URL`，按 [部署指南](DEPLOYMENT.md) 配置域名、反向代理与 HTTPS。本轮只提供部署基础，没有执行真实上线。
